# Регул — цифровой двойник теплицы

Рабочий локальный MVP для одной климатической зоны: журналы измерений, виртуальные эксперименты, сравнение затрат и журнал решений. Интерфейс на русском. Расчёты выполняет воспроизводимая приближённая модель; происхождение данных, её допущения и статус проверки доступны на странице «Модель и данные». Начальный журнал — пример, а не показания реального объекта.

## Запуск

Требуются Python 3.10+ и Node.js 20.19+ или 22.12+.

```bash
./start.sh
```

Первый запуск устанавливает зависимости. Интерфейс: http://127.0.0.1:5173, Swagger: http://127.0.0.1:8001/docs. Скрипт проверяет свободные порты, а при остановке завершает только свои процессы.

Если стандартные порты заняты:

```bash
KOLHOZ_BACKEND_PORT=8011 KOLHOZ_FRONTEND_PORT=5180 ./start.sh
```

Раздельная установка и запуск:

```bash
cd backend
python3 -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8001
```

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

SQLite хранится в `backend/data/kolhoz.db`. Альтернативное хранилище задаётся через `KOLHOZ_DB_PATH`. Импорт, настройки, паспорт, тарифы, сценарии, эксперименты, решения и версии калибровки сохраняются между запусками. Перед переносом или сбросом состояния сохраните копию базы.

## Возможности

- **Обзор:** показатели, интерактивная история, быстрый сценарий и крупная визуализация. Настоящая WebGL-сцена вращается, управляется мышью и стрелками; доступны фото, план и полноэкранный режим.
- **Модель в пространстве и времени:** метки привязаны к координатам теплицы и оборудования, ползунок выбирает запись журнала. Положение форточек и экранов, яркость ламп и труб отражают доступные значения. Цвет основания обозначает температуру всей зоны. Нет данных — явно показано; отдельные пространственные датчики не выдумываются. Просмотр без стекла открывает внутреннее устройство.
- **Текущий климат:** фильтры 6/12/24 часа, измерения и прогноз, погода и оборудование, пропуски, CSV.
- **Сценарии:** три варианта, общий старт и погода, горизонты 6/12/24 часа, отопление, вентиляция, экраны, досветка, CO₂. Результаты: климат, ресурсы, стоимость, ограничения, допущения. Сохранение шаблонов, история запусков, решение с обоснованием.
- **Модель и данные:** импорт CSV, предпросмотр, сопоставление столбцов, качество, редактируемый паспорт, калибровка прогноза на журнале, версии и прогноз/факт.
- **Экономика:** тарифы, периоды месяц/квартал/год, сравнение вариантов, расчёт окупаемости при заданных инвестициях. Модельная экономия отделена от подтверждённой.
- **Отчёты:** фильтры, история экспериментов, решения, архив, CSV и печатный PDF через диалог браузера.
- **Настройки:** объект, площадь, часовой пояс, единицы °C/°F и МВт·ч/кВт·ч, ограничения. Формы валидируются, ошибки показываются пользователю.

## CSV

UTF-8, разделитель запятая или точка с запятой, размер до 10 МБ. Обязательные столбцы: время, температура воздуха внутри теплицы и влажность. Автоматическое сопоставление можно изменить вручную. После проверки валидный импорт становится активным журналом; замена набора сбрасывает активную калибровку, сохранённые эксперименты сохраняют снимок исходных данных.

```csv
timestamp,temp_air,humidity,co2,ppfd,heating_valve,outdoor_temp
2026-10-10T09:00:00+03:00,22.1,68,820,320,40,6
2026-10-10T09:10:00+03:00,22.3,67,825,325,42,6.2
```

Время без смещения трактуется в выбранном часовом поясе. Канонические единицы импорта: °C, %, ppm, μmol/m²·s; солнечная радиация — Вт/м², положения оборудования — %. Автоматической конвертации единиц CSV нет. Неизвестные значения и разрывы не подменяются нулями. Проверяются числовые поля, диапазоны, дубликаты времени, пустые ячейки и частота. Есть необязательные колонки наружной температуры, солнечной радиации, вентиляции, экранов, досветки. Полный пример: `backend/data/sample_greenhouse_log.csv`.

## API-контракты

Префикс `/api`; схемы и примеры доступны в `/docs` и `/openapi.json`. Ошибки возвращают HTTP 4xx/5xx с `detail`; клиент отображает понятное сообщение.

| Метод и маршрут | Назначение |
| --- | --- |
| GET `/health` | Доступность сервера и статус локальной модели |
| GET `/climate/current` | Последнее состояние, цели, источник, время, доступные показатели |
| GET `/climate/history-24h` | Записи с временем, измерениями, прогнозом, погодой и оборудованием |
| GET `/climate/zones` | Одна зона А |
| POST `/data/upload` | Multipart `file`, проверка и применение корректного CSV |
| GET `/data/sample-csv` | Пример CSV |
| GET `/data/quality-default` | Проверка текущего подготовленного набора |
| GET/POST `/data/mapping` | Сопоставление и применение подготовленного журнала |
| GET/POST `/data/passport` | Паспорт зоны |
| GET `/model/status` | Источник, активная калибровка и версии |
| POST `/model/calibrate` | `{start?, end?}`: калибровка и проверка по времени |
| POST `/model/versions/{version}/activate` | Активация версии на совместимом наборе |
| GET `/model/forecast-fact?experiment_id=…` | Сопоставление прогноза с последующим фактом |
| GET `/experiments/presets` | Шаблоны параметров |
| POST `/experiments/preview` | Расчёт без записи истории |
| POST `/experiments/simulate` | Расчёт и сохранение полного снимка запуска |
| GET/POST `/experiments/scenarios` | Сохранённые настройки сценариев |
| DELETE `/experiments/scenarios/{name}` | Удаление шаблона |
| GET `/experiments/history` | Сохранённые запуски |
| GET `/economics/summary` | Проекция затрат и ресурсов |
| GET/POST `/economics/tariffs` | Тарифы и инвестиции |
| GET/POST `/reports/decisions` | Решения, привязанные к эксперименту |
| PATCH `/reports/decisions/{id}/archive` | Архивирование решения |
| GET/POST `/settings/` | Настройки и ограничения |

Пример расчёта:

```json
{
  "horizon_hours": 24,
  "custom_scenario": {
    "name": "Вариант A",
    "heating_temp": 22,
    "vent_min_open": 10,
    "screen_mode": "auto",
    "lighting_intensity": 300,
    "co2_target": 800,
    "night_temp_drop": 2
  }
}
```

Ответ содержит `series`, KPI вариантов, ограничения и допущения; сохранённый запуск также содержит `id`, `created_at`, `initial_state`, `request` и источник. API сохраняет `is_demo: true` для приближённого движка: интерфейс не выдаёт его за проверенную научную модель.

## Архитектура

Frontend: React + TypeScript, Vite, Tailwind, Lucide, Recharts, TanStack Query, Zustand, Radix Dialog, Three.js. Общие UI-компоненты находятся в `frontend/src/components/ui`, страницы — в `pages`, клиент — в `api`, состояние — в `store`, контракты — в `types`. Страницы, графики и WebGL загружаются отдельными чанками.

Backend: FastAPI + Pydantic + SQLite. Маршруты — `backend/app/api/endpoints`, контракты — `models`, хранилище — `db/store.py`; услуги данных, расчётов, экономики и отчётов разделены в `services`.

`BaseSimulationEngine` в `services/simulation_engine.py` задаёт границу подключения математической или ML-модели. Внешний адаптер должен принимать одинаковое начальное состояние и погодный ряд для всех вариантов, возвращать существующий `SimulationResult`, версию и допущения. Перед переключением требуется проверка модели на данных объекта.

## Проверки

```bash
cd backend
PYTHONPATH=. venv/bin/pytest -q
```

Backend-проверки используют отдельную SQLite-базу в каждой проверке.

```bash
cd frontend
npm run build
npm run verify:ui
```

UI-проверка требует установленный Chromium (`KOLHOZ_CHROMIUM_PATH` для другого пути). Она поднимает собственные серверы на 8017/5187 и браузер на 9337, создаёт отдельную базу, проверяет 3D, сценарии, решения, CSV, калибровку, настройки, экономику, PDF, мобильный экран и восстановление фокуса. Порты меняются через `KOLHOZ_TEST_API_PORT`, `KOLHOZ_TEST_WEB_PORT`, `KOLHOZ_TEST_CDP_PORT`. Скриншоты и PDF остаются в напечатанной временной папке; тестовое хранилище удаляется.

## Ограничения MVP

Одна зона; нет подключения датчиков, камер и управления оборудованием. Погода для сценариев задаётся воспроизводимым синтетическим рядом; CO₂ без измерений — явно указанное допущение. Локальный движок приближённый, его физика не валидирована на объекте. Калибровка относится к отдельному прогнозу по журналу: первые 80% записей используются для оценки дрейфа, следующие 20% — для последовательной проверки одного шага и сравнения с прогнозом последнего значения. Это не независимая валидация физического симулятора.

Прогноз/факт требует последующих измерений; подтверждённая экономия требует данных счётчиков и сопоставимого периода. PDF создаёт браузер, серверного PDF-генератора нет. Локальный MVP без авторизации и многопользовательского разграничения. Фото — созданная иллюстрация, геометрия 3D — условная модель; происхождение изображения описано в `frontend/public/assets/README.md`.
